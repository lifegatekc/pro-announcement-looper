# Pro Announcement Looper

An open-source ProPresenter announcements player for Roku, plus a separate companion screensaver. Built for a church running ProPresenter 21 and Roku Streaming Stick 4K devices, with a practical target of 4–6 unattended hours per day.

**Status: first implementation, compiler-checked and locally tested; not yet tested on a physical Roku or a live ProPresenter 21 installation.** Do not replace your Sunday setup before completing the hardware acceptance checks below. The source is published at https://github.com/lcberto/pro-announcement-looper. No Roku Store listing has been published.

## What it does

- Browse ProPresenter libraries and select a presentation by name. Saves its unique presentation ID, so a rename does not change which presentation is requested.
- Remember up to eight named profiles with separate presentations, durations, weekly/daily switch times, and caches. Main Service and Youth Service are just initial names.
- Download enabled slides at a requested longest dimension of 1920 pixels.
- Decode-check the downloaded images before making them active.
- Loop independently of ProPresenter's active presentation, service playlist, and Announcement Layer. It never triggers slides, starts timers, focuses presentations, or changes service output.
- Use a **0.3-second dissolve** between slides, with Play/Pause on the remote and in the controls menu.
- Default to **13 seconds per displayed slide**, adjustable from 1 to 3600 seconds. This is an app setting, not an imported ProPresenter timer.
- Cache compressed images in Roku's `cachefs:` and release old decoded images as playback advances. No ProPresenter requests during a healthy loop.
- Refresh manually while the existing slideshow continues. A failed refresh preserves the previous slideshow. The previous displayed image stays visible until the replacement decodes.
- Provide a companion system screensaver with its own settings/preview entry point and cache. If no usable cache exists, the screensaver attempts a download and retries once a minute until successful.
- Log uptime and completed loops once a minute, without accumulating an in-memory log.

This release displays slide images with its own dissolve. Thumbnails are not the live composited output: video, ProPresenter transitions, build animations, live data, and other layers may not appear as they do on your sanctuary screen. Confirm the artwork on your actual presentations.

## Download / build

Run `npm run build` to generate sideload ZIPs in `out/` (build outputs are not committed to Git):

- `pro-announcement-looper-player.zip`
- `pro-announcement-looper-screensaver.zip`

To work on the project, install Node.js 20+ and Python 3.9+, open this folder in VS Code, and install the recommended **BrightScript Language** extension from RokuCommunity.

```sh
npm ci
npm run check
npm test
npm run build
```

`check` compiles/validates both entry-point configurations with BrighterScript. `test` runs BrightScript data and refresh-state tests and Python mock API tests; the latter need permission to bind a loopback port. `build` creates both ZIPs and expanded `out/player` / `out/screensaver` folders. It does not deploy to a Roku.

The artwork is original, generated by `python3 scripts/assets.py`; no image service or paid dependency is needed.

## First run with your Roku and ProPresenter

1. Enable Developer Mode on a test Roku using Roku's official developer instructions. Visit the Roku's IP address in a browser and install `out/pro-announcement-looper-player.zip`.
2. In ProPresenter, enable its network/API access and note the computer's LAN IP and API port. The documented default is `50001`; use the actual value shown on your computer. The Roku must be able to reach that computer on your church network. Guest Wi-Fi/client isolation can prevent this.
3. Launch **Pro Announcement Looper**. Open **Connection & TV settings → ProPresenter address** and enter something like `192.168.1.50:50001`. A missing port defaults to 50001. Hostnames and IPv4 are supported; IPv6 literals, credentials in the URL, and URL paths are not supported in this release.
4. Open **Presentations → Add presentation**, choose a library, then choose the ProPresenter presentation. Only content added to this TV appears in the Presentations list. Existing configured presentations migrate automatically.
5. Select a presentation to open all its settings: **Show now**, source presentation, seconds per slide (1–3600, default 13), refresh, rename, and remove. Editing never changes the default or switches the displayed presentation. Removing it also removes its scheduled switches from this TV; the original in ProPresenter stays available.
6. Choose **Show now**. Missing slides are downloaded and validated first. With scheduling off, this starts playback and remembers the default. With scheduling on, choose **Until the next scheduled switch** or **Until I resume the schedule**. Home’s **Start slideshow** uses the current schedule, override, or saved default.
7. **Presentations → Refresh all** prepares all added presentations for scheduled switching. A presentation’s **Refresh slides** updates just that presentation. A failed refresh preserves the prior slides.
8. During playback, **\*** opens controls and holds the current slide; closing controls resumes it unless you had already paused with the remote. **Play/Pause** works during full-screen playback. Scheduled switches wait while the menu is open or playback is paused; explicit remote switches can override. Dissolves last 0.3 seconds.
9. **Back** during full-screen playback stops and returns Home. Back from presentation settings returns to the presentation list. **Left/Right** manually changes slides. **Home** leaves the app.

The player asks ProPresenter for JPEG thumbnails (`thumbnail_type=jpeg`) and also accepts PNG responses. HTTP/API authorization errors appear in the UI. There is no password/Bearer-token configuration in this release; if your installation requires API authentication, this must be adapted to its supported mechanism. This app does not bypass authorization.

## VS Code debugging

Run `npm run build`, then copy `.vscode/launch.example.json` to `.vscode/launch.json`. Launch **Pro Announcement Looper: player** and enter your test Roku address and developer password. Rebuild after editing sources because the debugger deploys the expanded `out/player` folder.

For the screensaver, sideload its ZIP and use Roku's screensaver **Preview** and **Change screensaver settings** entries. Its debug console uses port 8087; the normal player uses port 8085.

**Roku allows only one sideloaded developer app at a time.** Sideloading the companion replaces the sideloaded player. Simultaneous installation of both requires appropriate Roku distribution/signing; this is not solved by providing two ZIPs. Test them separately first. Store distribution also requires Roku certification, including applicable product-policy review.

## Screensaver installation and settings

Roku's current rules require the screensaver to be a standalone package. After installing it, choose **Settings → Theme → Screensavers → Pro Announcement Looper Screensaver → Set as screensaver**. Use its **Change screensaver settings** menu to configure the address, profiles, presentation, duration, refresh, schedules, and preview.

Both packages use the registry section `ProAnnouncementLooperV1`. Registry sharing requires the same developer signing key. Without that, configure them separately. An installed player and screensaver sharing that key read the same saved settings when launched; they do not live-sync changes into an already running slideshow.

The compressed-image caches are deliberately separate. This avoids one running context deleting files used by the other. The screensaver may therefore download the selected deck once even when the player has already cached it. Refresh the screensaver's cache through **Change screensaver settings → Presentations → Refresh all**. There are no interactive controls inside a running system screensaver: a remote key exits it under Roku's normal rules.

A manually started player must respect the system screensaver. For church deployment, select the announcements companion so that idle takeover continues showing announcements. Test that transition on the target OS/device. This project does not fake remote key presses, play a dummy video, or override the system screensaver.

## Settings navigation and single-slide behavior

Home contains **Start slideshow**, **Presentations**, **Schedule**, and **Connection & TV settings**.

**Presentations** lists configured content and identifies what is showing (or the saved default). Selecting an entry edits it without activating it. **Add presentation** browses ProPresenter; **Refresh all** checks all configured content. Each presentation’s settings include **Show now**, source, duration, refresh, automatic refresh interval, rename, and remove.

**Schedule** belongs to the TV. Its switch list combines all presentations in chronological weekly order. Every switch includes a target presentation and editable day/time. **Resume schedule** clears a manual override. Settings and cached content are preserved across the menu reorganization.

**One enabled slide stays on screen indefinitely** with no advancement timer and no repeated dissolve into itself. Refresh and scheduled profile changes still work. Left/Right does nothing for a one-slide deck. With two or more slides, every enabled cue is shown in order—even duplicate images—so two identical images remain visible for two slide intervals. Start slideshow starts playback immediately; Play/Pause is only needed to pause or resume an existing session. OK only selects menu items, so the button press that starts a slideshow cannot also pause it. Playback pause state is not persisted between launches.

## Scheduled switching, manual holds, and optional remote actions

Each TV stores its own configuration. You can create profiles named **Kids Check-in Open**, **Check-in Closed**, **Lobby Welcome**, **Event**, or any other label, with a different ProPresenter presentation for each. A one-slide presentation simply stays on that image.

Open **Schedule → View / edit switch times → Add switch time**. Choose what to show, day (or **Every day**), hour, minute, and AM/PM, then **Save switch time**. Open an existing switch to change any field or delete it. The minute picker supports Up/Down for one-minute steps and Left/Right for ten-minute jumps. All presentations’ switches appear together. Limits: eight presentations and sixteen switches per presentation. Existing schedules migrate unchanged.

Example for two Sunday services:

| Profile | Switch times |
| --- | --- |
| Kids Check-in Open | `Sun 08:30, Sun 10:30` |
| Check-in Closed | `Sun 09:00, Sun 11:00` |

Choose the presentation for each profile, choose **Presentations → Refresh all**, turn **Schedule** on, then **Start slideshow**. The scheduler checks every five seconds and uses the Roku's configured local time/timezone, including its daylight-saving conversion. Confirm the device clock/timezone before deployment. It chooses the latest recurring switch in the past week, so a late launch catches up to the current state. A selected state remains until the next switch; there is no implicit midnight reset. Include reopening times explicitly. Equal switch times resolve to the lower profile number.

Schedules are evaluated while full-screen playback is active, including the system screensaver. The regular player's settings menu pauses automatic switches while you edit; close it to apply the current scheduled state. An app that is closed, a powered-off TV, or a sleeping Roku cannot execute schedules. This feature does not wake or launch the app.

**Presentations → [presentation] → Show now** explicitly activates content. With scheduling off, it becomes the saved default. With scheduling on, a temporary override lasts until the next scheduled event, or a hold lasts until **Schedule → Resume schedule**. Both choices survive reopening through saved settings; temporary overrides retain their original deadline. A temporary override requires at least one scheduled event. Show now downloads missing slides before activating; an offline failure leaves the current presentation available. Normal scheduled switches require a ready cache and never fetch implicitly during healthy playback.

Each profile refresh is atomic independently: if refreshing all profiles fails partway, already-completed profiles retain their new caches and remaining profiles retain their old caches. There is no cross-profile all-or-nothing transaction.

### Remote action (regular player only)

Remote actions default to **Off**. Enable them in the player's menu when wanted. With the regular player running in the foreground, another local device can send Roku ECP commands:

```sh
# Show profile 3 and hold it until Resume schedule.
curl -X POST 'http://ROKU_IP:8060/input?palAction=switch&profile=3'

# Refresh every configured presentation (refreshAll is also accepted).
curl -X POST 'http://ROKU_IP:8060/input?palAction=refresh'

# Refresh only presentation 3, without switching to it.
curl -X POST 'http://ROKU_IP:8060/input?palAction=refresh&profile=3'

# Clear the manual hold and apply the current scheduled state.
curl -X POST 'http://ROKU_IP:8060/input?palAction=resume'
```

Remote numbers use stable internal slots (1–8), shown in the presentation side card when remote actions are enabled. Removing a presentation does not renumber survivors; adding another can reuse the removed number. Update external remote commands if you reuse a slot. A remote switch requires the target cache to be ready. Remote refresh uses the normal validated cache replacement: unchanged images retain their cache and playback position, failures preserve old slides, and refreshing inactive content never activates it. Refresh does not change the default, schedule, or manual hold. Commands received during a refresh wait until it finishes; the most recent command wins. HTTP acknowledgement from Roku means delivery to ECP, not proof that the selected profile displayed successfully.

Use the Roku OS settings required for local network control; OS/device restrictions may apply. Commands use Roku's existing local ECP interface, with no app authentication added by this project. Keep it on your intended local network. This is not an internet endpoint. It does not install a Companion/Stream Deck/Home Assistant integration or automatically watch a ProPresenter service cue; those can send the documented request if configured separately.

The standalone screensaver does not register these remote inputs, consistent with its noninteractive design. Its schedule still works. To override its selection, exit to its settings and choose the desired manual hold; configure remote-triggered workflows using the regular foreground player. This distinction needs testing on the target OS/device.

## Unattended use: 4–6 hours

These are device settings; the app does not silently change them:

- **Settings → Network → Bandwidth saver → Off.** Roku's documented four-hour rule applies to streaming; verify cached-image playback as part of the hardware test.
- **Settings → System → Power → Auto power savings:** uncheck **After 20 minutes of no interaction**, if present. Roku lists Streaming Stick 4K model 3820 as supporting this setting.
- Select the announcements companion as the system screensaver for installations that include it. While testing only the sideloaded player, you may manually disable the system screensaver in Roku settings to isolate the player runtime test; restore your preferred setting afterward.
- Check the TV's own sleep/eco timer, and keep the stick powered throughout the session. Roku recommends its included wall adapter and cable for this model.

There is no promise of surviving an OS update, reboot, Home press, or OS termination. A system screensaver is not a crash watchdog. Memory monitoring is enabled where supported, refresh validation is stopped on a high-memory warning, and playback keeps only the current and loading slide decoded (plus one temporary validation image during refresh).

## Cache behavior

Cache files are compressed JPEG/PNG downloads, not a collection of decoded full-resolution bitmaps. Cache limits are **100 enabled slides**, **4 MiB per image**, and **32 MiB per deck**. Each profile retains its own deck; a refresh retains its old deck until the candidate is ready. Cache generation directories are isolated by profile. A 64 MiB budget bounds indexed profile caches plus the replacement download per app (up to one image of transient overshoot). These limits are conservative starting values, not a measured guarantee for every Roku model.

`cachefs:` is managed by Roku and may be evicted at any time. On sticks it is RAM-backed; restarting can clear it, which is acceptable for this use case. If an individual file disappears during playback, retain the last displayed image and try the next slide at the normal interval. A notice asks for refresh. The app contacts ProPresenter during playback only for explicit refreshes or enabled automatic refresh intervals.

A candidate deck is downloaded under a new generation prefix. Every image must decode in a hidden, bounded-size Poster before the worker commits the index. Incomplete/corrupt candidates are discarded; the prior deck remains active. The next refresh or startup removes stale generations. A crash during index writing can require a fresh download, which is acceptable because restart survival is outside scope.

Opening the player or starting the screensaver automatically checks every configured profile, checking the currently scheduled or held profile first. Cached screensaver slides start immediately while the check runs; in the player, **Start slideshow** can use the existing cache during the check. If ProPresenter is unavailable, the existing cache remains available.

ProPresenter does not supply a reliable image revision or conditional-download header, so each startup check downloads the slide images once and compares their ordered SHA-256 fingerprints with the cache. Identical images retain the current cache and playback position. Added, removed, reordered, or changed images are validated before replacing that profile’s cache. Manual refresh remains available. By default, healthy playback makes no further automatic refresh requests until the next launch. Enable **Presentations → [presentation] → Auto refresh** to check periodically in both the regular player and system screensaver. Options are **On open only** (default), 1, 5, 10, 15, 30, 60, or 120 minutes. Each presentation has its own interval, including content not currently showing. Checks run during full-screen, unpaused playback, wait while menus, other requests, or memory pressure are active, and prioritize the currently displayed presentation. A due check starts on the next five-second scheduler tick after the interval.

Automatic checks download and compare rendered images once per interval; they do not poll only a presentation title or slide count, which would miss artwork-only changes. Budget local-network traffic as deck download size × checks per hour × TVs. Unchanged checks preserve playback position. Validated changed decks replace active content at the next normal slide boundary; a one-slide deck updates once validation finishes because it has no advance timer. No progress/error overlay interrupts playback. Failed checks retain old content and wait a full interval before retrying. Manual and startup checks reset the interval as well. Each image is held for the configured duration after it loads; there may be a small extra decode delay during transitions. This is independent playback, not frame synchronization with ProPresenter.

## Try it without touching church output

```sh
npm run mock
```

Enter your development computer's LAN address and port 50001 in the Roku app. Choose the **Church** library and either sample presentation. The mock serves three original 1920×1080 slides and includes a disabled cue between groups to test flat slide numbering.

To simulate a failed refresh, stop the mock and restart it with:

```sh
python3 scripts/mock_server.py --fail-slide 2
```

For a corrupt image or changed image content:

```sh
python3 scripts/mock_server.py --corrupt-slide 2
python3 scripts/mock_server.py --revision 1
```

Run only one mock server at a time. Stop it with Ctrl+C. Use `--port` if ProPresenter or another app already uses 50001. The default mock binds all local network interfaces so a Roku can connect; `npm test` binds only loopback and shuts the mock down afterward.

## Hardware acceptance before church deployment

- Confirm both real announcement presentations are discoverable in ProPresenter 21 and all enabled slides look correct and legible on the TV. Verify slide order, duplicates, disabled cues, and group boundaries against the intended presentation arrangement; adjust flattening if your API returns a different ordering.
- Run the player for **at least six hours without remote interaction**, beyond the 20-minute and four-hour thresholds. Repeat for the companion screensaver. Confirm no exit, blank screen, TV power-off, or unwanted screensaver replacement.
- Disconnect Wi-Fi or close ProPresenter after caching. Confirm the loop continues. Confirm a failed refresh preserves old slides; restore the connection and successfully refresh edited content.
- Test a corrupt candidate image using the mock. Confirm every old slide remains available and no partial deck is promoted.
- Test named profile switching, schedule boundaries, weekly rollover, multiple services, local timezone, manual hold/resume, optional remote switch/resume, cache loss at a scheduled boundary, profile persistence, duration changes, Back/Home behavior, and screensaver entry/exit. Test the real installation/distribution method if both packages will coexist.
- Watch memory over the six-hour run, including repeated refreshes. There should be no steady rise in retained images/nodes. Check OS memory events and logs using Roku's developer tools.

No physical-device, live-ProPresenter, visual-rendering, or six-hour runtime checks have been performed in the development environment used to generate this project. Passing the local compiler and mocks does not substitute for these tests.

## Architecture

- `source/model.brs`: settings validation, presentation parsing, slide ordinals, cache identity.
- `components/ApiWorker.*`: asynchronous network work and registry/filesystem operations, away from the render thread.
- `components/AnnouncementsScene.*`: remote-driven settings, bounded image playback, decode validation, refresh handoff.
- `source/player.brs`: regular app entry point.
- `source/screensaver.brs`: standalone screensaver and settings entry points.
- `scripts/`: repeatable packaging, artwork, mock server, local checks.
- `tests/`: executable BrightScript data/state tests and mock endpoint tests.

The only ProPresenter endpoints used are read-only:

```text
GET /v1/libraries
GET /v1/library/{library_name}
GET /v1/presentation/{uuid}
GET /v1/presentation/{uuid}/thumbnail/{index}?quality=1920&thumbnail_type=jpeg
```
